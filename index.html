🔹 Bug Fixes

Pro answers incorrectly flagged as thinking/meta
  • Issue: Valid Pro responses were rejected with "Invalid response capture: captured thinking/meta UI instead of final answer".
    • Symptoms:
      • UI showed a complete answer but runner retried the same row.
        • Failures were more frequent on Expert/Pro responses with richer UI widgets.
          • Root Cause: isLikelyThinkingOrMetaText() in content.js used an overly broad regex pattern that matched generic words like "results", causing false positives in answers containing normal prose.
            • Fix: Tightened meta detection:

              • 1. Detect only short status-like lines such as "Thought for 16s", "3 results", "sources 135".

              2. Require extracted text to be predominantly meta lines before rejecting.

              3. Add a short-length guard (max 240 chars) so full prose answers are not rejected.

              • Outcome:
                • Complete Pro responses now pass validation correctly.
                  • Retry loops from false meta detection are eliminated.
